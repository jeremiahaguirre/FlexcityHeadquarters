# Feature audit — November 2026

What FH is missing, or could do better, after the payroll, isolation and scale work. Each item says what was checked in the code, why it matters to a Canadian city, and roughly how big it is (S = days, M = a week or two, L = several weeks). Items already on the [roadmap](ROADMAP.md) are marked.

Sections 1 and 2 were built in November 2026, except 2.7 (facility safety checks); the Status column says what was built and where. Sections 3 and 4 are as audited, except 3.4 (offline punching), built in November 2026.

The [launch blockers on the roadmap](ROADMAP.md#before-the-first-customer) still come first: legal review of the provincial rules and the consent agreement, provider API access, and Revenu Québec's RL-1 authorization. Nothing below replaces them.

## 4. Engineering improvements

| # | What | Today | Suggested |
| --- | --- | --- | --- |
| 4.1 | **Error tracking and metrics** | Logs (`lib/log.ts`) and `/healthz`, which doesn't touch the database. | Done (Nov 2026): `/readyz` runs `SELECT 1` with a short timeout and reports the email and text backlog and the worker's heartbeat (503 with reasons when not ready). Every request has an id (`X-Request-Id`, in logs and error bodies). `/metrics` in Prometheus format behind `METRICS_TOKEN`: requests and latency by route pattern, errors, query time, memory, event-loop delay, outbox backlog. Server and browser errors go to a Sentry-compatible service when `SENTRY_DSN` is set, scrubbed of personal information and rate-limited. Not yet: Prisma's connection-pool metrics (a preview feature that needs a schema flag). See [ARCHITECTURE.md](ARCHITECTURE.md#health-metrics-and-errors). |
| 4.2 | **Notifications that survive a crash** | Domain events are published in memory after the transaction commits (`lib/events.ts`). If the process stops between the commit and `handleEvent`, that notification is lost. | Done (Nov 2026): events are written to `EventOutbox` in the same transaction as the change (RLS), delivered straight after the commit by the same process and every 5 s by the worker as the backstop. Claims use `FOR UPDATE SKIP LOCKED`; the handler and the delivered mark commit together, so delivery is at least once; notifications carry a dedupe key so a redelivery adds nothing. Failures back off (5 s → 10 min) and go dead after 8 tries (shown in `/readyz` and `/metrics`). Delivered events are cleared after 7 days. Urgent open-shift texts go through it; working-alone alerts, calls for help and call-outs already write their notification, text and call in the change's own transaction. See [ARCHITECTURE.md](ARCHITECTURE.md#events). |
| 4.3 | **More than one API process** | At a realistic pace one process answers in under 50 ms (p99). With all 9,030 load-test workers acting at the same moment, reads take 1.6 s (p50) on one process and 0.95 s on three, with no errors. | Done (Nov 2026): processes share nothing in memory. Live notifications use one `LISTEN` connection per process (ids only, reconnects and tells streams to refetch); caches are dropped in every process through `pg_notify` and expire within 30–60 s anyway; rate limits use Postgres whenever several processes run; scheduled jobs run only in the worker, under advisory locks. Run `WEB_CONCURRENCY` (one per core) or several instances (request traffic may go through PgBouncer in transaction mode; the `LISTEN` and worker connections must be direct). See [ARCHITECTURE.md](ARCHITECTURE.md#process-model) and [SCALABILITY.md](SCALABILITY.md). |
| 4.4 | Labels built at run time | Fixed in this pass: a test now fails when a feature switch or journal account has no English or French label. | Do the same wherever a key is built from server data, such as notification types and reason codes. |
| 4.5 | French bottom bar on small phones | At 390 px some French tab labels are cut short ("Aujourd'…", "Approba…"). | Done: the bottom bar uses its own short labels in both languages (`nav.*Short`), e.g. “Demandes”, “Heures sup”. |

## What was checked and is in good shape

- **One city can't see another's data**:
  - row-level security and a policy on every table with a city or invoice id;
  - a sweep of 2,944 requests over 382 routes using the other city's ids found nothing returned or changed;
  - benchmarks are published only as quartiles, only from cities that share, and only once five or more do.
- **Payroll**:
  - hourly and salaried pay, adjustments, off-cycle runs, orders, two positions, multiple facilities, all 13 jurisdictions;
  - two-person approval, and provider mode that locks out in-app approval.
- **SQL injection**: no SQL is built from values (enforced by a CI guard), the database role has least privilege, and statements have time limits.
- **App, Dev console and website**: a live click-through of every role in English and French. Its findings were fixed in this pass.
